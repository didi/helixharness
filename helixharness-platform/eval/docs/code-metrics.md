# 归档代码统计

看板从当前 `helixharness-eval-ledger/1.0` 中读取已完成的 Archive 记录，按需求统计一次归档净代码变化。重复 Apply 或 Archive 记录不会重复累加同一需求的净增量；这些统计仅用于展示，不作为 Bench 评分证据。

提交与范围必须来自固定证据：

- 已封存实现提交使用 `checkpoint.implementation_commit_id` 和 `reviewed_paths`；存在冻结的 `review_fixed_point` 时，以它作为完整需求基线。只有未提供评审基线时才使用固定的 `base_commit`；已提供但无效的评审基线会阻断统计，不能回退。这样代码在 Archive 开始前已经提交时，也不会被误算为零。
- 当前插件以分支方式归档且未提供实现提交时，必须显式记录 `code_resolution=branch`、`review_fixed_point`、`review_head` 与 `reviewed_paths`。同时核验已记录的 `head_commit` 等于冻结的 Review Head，且基线是其祖先。
- 提交方式不读取旧字段别名；两种当前归档方式都不使用此刻工作区、分支最新 HEAD 或未提交改动补足证据。

缺少提交、范围、同步对象或有效归档记录时显示具体的不可用原因，不能填为零。存在可信空 diff 时才记为零；二进制文件单独计数，不伪造增删行数。生产代码、测试、文档和其他文件分别汇总。

归档文档的发现也按固定证据校验：候选提交中的需求身份、归档记录、提交父子关系和工件列表必须匹配。存在多个匹配提交或超过检索上限时保持不可用，不从当前工作区猜测。代码与文档读取只形成可重建投影，不修改原账本或历史 Run。
