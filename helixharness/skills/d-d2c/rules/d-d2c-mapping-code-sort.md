## 任务目标

请基于当前代码仓库，系统梳理以下两类内容，并输出为结构化文档：

1. 当前项目 `assets` 中有哪些可复用物料
2. 当前项目依赖的组件库中有哪些组件、组件能力和使用方式

这些输出将作为后续编写以下文档的依据：

- `assets-mapping.md`
- `components-mapping.md`

请注意：本次任务的目标是“盘点”和“归类”，不是直接建立设计稿映射关系，也不是修改代码。

## 分析范围

请优先分析以下内容：

# 一、assets 相关

## 任务要求

### 1. 先识别项目结构

请先识别：

- assets 目录位置
- 公共样式目录位置
- icon / image / font / token / theme 文件位置
- 通用组件库目录位置

### 2. 盘点 assets

请梳理出当前仓库中 assets 的分类，并尽量按“可映射性”整理，而不是只按文件后缀罗列。

建议输出维度包括：

- 类别
- 名称/路径
- 用途
- 是否公共复用
- 是否与设计稿映射强相关
- 是否存在状态变体
- 是否可能沉淀到 assets-mapping.md

重点关注以下类别：

- 图标类
- 图片类
- 字体类
- 样式变量/token 类
- 公共样式类
- 状态样式类
- 装饰资源类
- 业务专属资源类

### 3. 盘点组件库

请梳理组件库和组件使用情况，重点不是简单列文件名，而是尽可能总结“组件能力”。

建议输出维度包括：

- 组件名
- 所属来源（自研组件库 / 外部组件库 / 业务组件）
- 组件路径
- 组件用途
- 常见 props / slots / children 模式
- 支持的状态（disabled / loading / size / type 等）
- 是否高频复用
- 是否适合做设计组件映射
- 是否为基础组件 / 复合组件 / 业务组件

重点区分：

- 基础原子组件（Button、Input、Select、Modal、Tag、Avatar 等）
- 布局组件（Grid、Flex、Layout、Container、Space 等）
- 展示组件（Card、Table、Tabs、Collapse、Tooltip 等）
- 表单组件
- 反馈组件
- 导航组件
- 业务复合组件
- 页面私有组件

### 4. 分析真实使用情况

除了定义，还请尽量分析：

- 哪些组件在项目中被高频使用
- 哪些 assets 被高频引用
- 哪些组件/样式看起来已经形成事实标准
- 哪些组件虽然存在，但几乎没被使用
- 哪些地方存在重复实现，后续可能影响映射标准化

### 5. 输出时不要只做“文件树”

我不需要纯文件列表，我更需要“面向 D2C 建模”的盘点结果。

请尽量从以下角度组织输出：

- 哪些内容可以作为 D2C 的标准资产
- 哪些内容可以作为设计稿到代码的映射对象
- 哪些内容还不适合直接映射，原因是什么
- 哪些内容后续还需要人工补规则

### 6. 不要臆测

- 如果仓库中无法确认，就明确写“待确认”
- 不要虚构组件能力
- 不要虚构资产用途
- 优先基于真实代码定义、真实 import、真实使用位置得出结论
